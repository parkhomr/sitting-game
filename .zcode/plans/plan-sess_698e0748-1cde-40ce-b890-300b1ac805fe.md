# Per-hero base attack sounds — Labyrinth (synth + drop-in + lo-fi toggle)

## Context
The labyrinth game's 10 Dota 2 heroes (`drow, timber, sf, rubick, sniper, cm, jugger, mars, witch, magnus` in `dist/labyrinth-data.js:3-14`) attack silently. Goal: every successful basic attack plays that hero's base attack (projectile-launch) sound, heard by every client in the lobby. Multiplayer already broadcasts `world.events` to all clients (full-state clone per tick in `server.mjs`), so this needs: an engine event + client audio consumption + a per-hero sound engine.

Sourcing: Valve's real audio can't be fetched/bundled (copyright). Per agreed approach: original per-hero WebAudio synths designed from the Liquipedia sound catalogs (factual reference only), a drop-in slot for files the user extracts from their own install, and a "Pixelate" lo-fi toggle that live-degrades attack audio (no transformed files stored).

## Changes

### 1. `dist/labyrinth-engine.js` — emit the attack event
In `attack(w,p)` (line ~177), after the `if(p.attackCD>0)return` gate, emit once per successful attack near the end of the function: `event(w,'attack',{player:p.id,hero:p.hero})` — same pattern as the existing `cast` event (line 228). Nothing else changes; events already reach all clients.

### 2. `dist/labyrinth-audio.js` — per-hero sound engine (keep existing `{unlock,play,setMuted}` API)
- `noise(start,length,volume,filterFreq)` helper (buffer source + biquad) alongside existing `tone()`.
- Exported pure recipe table `LAB_ATTACK_SOUNDS`: hero id → 1–4 tone/noise descriptors. Original designs: `drow` icy bow twang + shimmer · `timber` chainsaw-rev sawtooth wobble · `sf` dark low sweep + breath puff · `rubick` quick arcane chirp up · `sniper` tight rifle crack (square + noise snap) · `cm` glassy high sines · `jugger` blade whoosh + metallic tick · `mars` heavy spear whoosh · `witch` wobbly voodoo triangle bounce · `magnus` low horn blare + shove.
- `playAttack(heroId)`: respects `muted`/context state; plays a cached drop-in sample if loaded, else renders the recipe. Per-hero ~60 ms rate limit (hold-attack spam). Overlapping attacks allowed.
- Drop-in loading in `unlock()`: per hero, `fetch('sounds/heroes/<id>.mp3'|'.ogg'|'.wav')` → `decodeAudioData` → cache; any failure = silent synth fallback (works when served; offline bundle gets synth only).
- Lo-fi chain: lazily built on unlock — `attackBus` gain → [WaveShaper with staircase quantize curve (≈8-bit) + lowpass ~3 kHz] → destination. `setPixelated(v)` rewires `attackBus` between dry and crush chain. All attack audio (synth + drop-in samples) routes through `attackBus`.

### 3. `dist/labyrinth-client.js` — consume event + toggle wiring
- `observeAudio()` (line 7): the watermark loop also handles `e.type==='attack'` → `labAudio.playAttack(e.hero)`.
- Wire `$('fxToggle')` like the existing `soundToggle` handler (line 64): toggles `data-pixel`, label "Pixelate: off/on", calls `labAudio.setPixelated(...)`.

### 4. `dist/labyrinth.html` — toggle button
Add `<button id="fxToggle" data-pixel="false">Pixelate: off</button>` in the controls row next to `soundToggle` (line 4).

### 5. `server.mjs` — serve drop-in files
Static serving is an exact-name whitelist (line 15, `files.get` at line 137). Add: `GET /sounds/heroes/<name>.<mp3|ogg|wav>` → read `dist/sounds/heroes/<name>.<ext>` if present (audio MIME), else 404. Commit only `dist/sounds/heroes/README.txt` documenting expected file names (`drow.mp3`, `sniper.mp3`, …) and that real Dota files are the user's own extraction for personal use.

### 6. Repackage
Run `npm run package` → regenerates root `labyrinth.html`, `downloads/labyrinth.html`, and the zips. No `package-local.mjs` list changes needed (all audio code lives inside existing modules).

### 7. Tests — `test/labyrinth-attack-sound.test.mjs` (node:test, mirroring `test/labyrinth-melee.test.mjs` harness style)
- Engine: each of the 10 heroes → one attack command ⇒ exactly one new `attack` event with correct `player`/`hero`; immediate second attack (cooldown) ⇒ no extra event; events survive JSON roundtrip.
- Audio (Node stubs, per the established stub pattern): every `HEROES` id has a well-formed recipe (finite freqs, sane volumes); stubbed `window.AudioContext` (records oscillator/buffer/gain/waveshaper/filter nodes) → `unlock()`+`playAttack('sniper')` schedules nodes; muted/locked context schedules none; `setPixelated(true)` routes through waveshaper+filter nodes.
